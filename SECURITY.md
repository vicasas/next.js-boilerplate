## Reporting a vulnerability

If you discover a security vulnerability, please report it responsibly and privately.

**Do not disclose security vulnerabilities through public GitHub Issues, Pull Requests, or Discussions.**

Use one of the following private reporting methods, in order of preference:

1. **GitHub Private Vulnerability Reporting:** If enabled for this repository, use the [Report a vulnerability](https://github.com/vicasas/next.js-boilerplate/security/advisories/new) feature to submit a private report through GitHub.
2. **Email:** If private vulnerability reporting is unavailable, contact the repository maintainers at [INSERT CONTACT EMAIL].

When reporting a vulnerability, provide as much relevant information as possible:

- A clear description of the vulnerability.
- The affected version, component, file, dependency, or branch.
- The potential security impact and severity.
- Steps to reproduce the issue.
- A proof of concept or exploit details, if available and safe to share.
- Any suggested mitigation or remediation.

Please avoid including real credentials, personal information, or sensitive production data in your report. Use dummy data whenever possible.

## Disclosure policy

We ask security researchers to allow maintainers reasonable time to investigate and address a vulnerability before publicly disclosing it.

Security reports will be handled confidentially whenever possible.

Once a vulnerability has been addressed, the maintainers may publish a security advisory describing the issue, its impact, affected versions, and remediation steps.

Contributors who responsibly report security vulnerabilities may be acknowledged, subject to their preference.

## Scope

This policy applies to security vulnerabilities directly affecting the code and configuration maintained in this repository.

Third-party dependencies and services may have their own security policies and reporting procedures. Vulnerabilities originating exclusively in third-party software should generally be reported to their respective maintainers, although vulnerabilities related to this project's dependency configuration may also be reported here.

Thank you for helping keep this project secure.
